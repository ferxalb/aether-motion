# AETHER Motion — Agent Guide

## Language policy

All human-readable content in this repository must be in English, including documentation, comments, examples, CLI and MCP descriptions, error messages, and test messages. Write all new content in English and translate existing prose into English when editing it. Preserve code identifiers, protocol terms, and program behavior.

## Code organization and maintainability

- Keep the code modular. Group related modules into clearly named folders by domain or responsibility so files are easy to locate and recognize. Avoid generic catch-all folders and monolithic files that mix unrelated concerns.
- Split large files when they combine distinct responsibilities or become difficult to navigate. In particular, do not keep expanding `src/parse.rs` and `src/render.rs` as catch-all modules: extract cohesive areas into clearly named submodules and keep their entry points as small, easy-to-find facades.
- Give each module a focused responsibility and expose small, explicit interfaces so components can evolve independently. Keep boundaries clear between core logic, parsing, rendering, I/O, and external integrations.
- Start every source file with a concise English file-level comment describing its purpose, scope, and main responsibility. Use Rust module documentation (`//!`) for Rust files. Update this documentation when a file's responsibilities, interfaces, or place in the module structure changes; keep it useful without repeating implementation details.
- Keep related architecture and usage documentation in sync as the project grows. When a change adds or moves modules, update relevant file-level documentation and the repository's architecture or contributor guidance.
- Apply established design patterns when they fit the problem and the existing architecture. Prefer simple, reusable abstractions and low coupling; avoid patterns that add complexity without a concrete benefit.
- Treat runtime optimization separately from code organization: profile before making performance-focused changes, and do not claim a refactor is faster without measurements. Preserve deterministic output.
- Make changes with future scalability and maintainability in mind, keeping dependencies and responsibilities clear as the system grows.

Create, validate, inspect, and render HTML compositions. Output must be deterministic: what appears in a frame is a function of time.

## Agent skills

- After a substantial change to a user-facing capability, supported composition contract, CLI or MCP workflow, block catalog, or rendering behavior, review the skills in `skills/`. Update the relevant existing skill or add a focused skill when the change introduces a distinct, recurring workflow.
- Keep skills aligned with the actual implementation and supported contract. Organize them around durable tasks as the repository grows; avoid duplicating reference documentation or creating one-off skills for isolated changes.
- Validate any new or updated skill before completing the change.

## Work loop

1. Run `aether-motion check <file.html>`. It returns JSON with `ok`, structure, and, on failure, `error` and `fix`. Continue until `ok: true`. It also probes text at 9 midpoint times and reports `layout.findings`: `outside_safe_zone` warnings (platform zones TikTok, Reels, and Shorts on 9:16 frames; 10% `standard` margins on other frames) and, with `--caption-zone "x0=0;y0=0.7;x1=1;y1=1[;severity=error]"`, `caption_zone_collision`. Options: `--safe-zone tiktok|reels|shorts|standard|off` (comma list), `--samples N`, `--at t1,t2`, `--strict` (makes caption-zone warnings fail; safe-zone warnings never fail). Exit codes: 0 ok, 1 invalid composition or a gating finding, 2 usage error. Opt out with `data-layout-allow-safe-zone` or `data-layout-allow-caption-zone` on the text or any ancestor (for `data-hf-captions`, put it on the captions element). Findings are grouped by the nearest ancestor with an `id` and reported at the first sampled time. Reels, Shorts, and `standard` follow HyperFrames' documented zones; TikTok uses the In-Feed template (720x1280: 160 top, 440 bottom, 80 sides, 200-wide button column from 720 above the bottom), scaled. Zones are reference guides. Text inside rotated elements is not measured; `overflow: hidden`, blur, and reveal layers are measured and cut to the part they show.
2. Inspect the result with `aether-motion render <file.html> --output frame.png --frame N` or the `aether_snapshot` MCP tool.
3. For 16:9 or 9:16 compositions, choose `--size 1080p` or `--size 4k` and `--fps 30` or `--fps 60`. The native encoder writes one MP4 sample per frame. `--quality draft|standard|high|max` (default `standard`, which reproduces exports from before presets existed) sets the fixed H.264 quantizer (30, 26, 22, 18); lower quantizers make larger files at nearly the same CPU cost.
4. Render the video with `aether-motion render <file.html> --output video.mp4`. On a terminal it redraws one progress line on stderr (percent, frames, fps, ETA); `--progress json` writes one JSON object per update on stderr (`done`, `total`, `fraction`, `fps`, `elapsedMs`, `etaMs`) and `--progress off` silences it. Progress never changes the output. For a template with composition variables, add `--variables '{"id": value}'` or `--variables-file values.json` to `check`, `render`, and `preview`.

## Supported contract

- The root has `data-composition-id`, `data-width`, `data-height`, and `data-duration`, either on the root element or on `<meta>`.
- Each clip uses `class="clip"`, `data-start` (seconds or another clip's `id`, optionally with a `+` or `-` offset), `data-duration`, and `data-track-index`.
- Supported elements include `div`, text, local `img` files (PNG, JPEG, WebP, or SVG), and inline `<svg>`. SVG is rasterized deterministically at the target size (`object-fit` applies; needs an explicit `width`/`height`): shapes, paths, strokes, gradients, clip paths, masks, and filters render; `<text>`, `<script>`, animation elements, `<foreignObject>`, event handlers, and non-`#fragment` references are errors or ignored. Motion comes from the element's own `data-hf-*` attributes (including `data-hf-draw` for self-drawing strokes), not from SMIL. Styles may be inline or use type, class, and ID selectors.
- Supported properties include `left`, `top`, `width`, `height`, and `max-width` in px or %, colors, `opacity`, `font-size` in px, `font-family`, `font-weight` (`normal`, `bold`, or 1-1000; inherited, resolved against installed font faces), `font-style` (`normal`, `italic`, `oblique`; inherited; an installed italic face is used, otherwise the upright face is slanted by 14 degrees around the baseline, as browsers synthesize it, so advances and line breaks do not change; `<em>` and `<i>` default to italic), `font-kerning` (inherited; `normal` applies the font's pair kerning from its GPOS `kern` feature or legacy `kern` table, matching a shaping engine on the embedded Roboto; `auto`, the default, and `none` keep the unkerned layout, so existing compositions lay out as before), `letter-spacing` in px (inherited, may be negative), `text-align`, centered flex layout, `object-fit`, and `z-index`.
- `overflow: hidden` clips an element's content (text, image, children) to its padding box, following `border-radius`; its own background, border, and shadow are not clipped, and `overflow: visible` is the default. Other values are errors. Clipped content renders on an offscreen layer, so very large clipped boxes can need `--scale`.
- `clip-path` (also `-webkit-clip-path`) keeps only the part of the element inside a basic shape, with antialiased edges: `inset(top right bottom left [round Npx])` (1 to 4 values), `circle(r [at x y])`, `ellipse(rx ry [at x y])`, and `polygon([nonzero,] x y, ...)` (3 to 256 points). Values are px or % of the border box (a circle's % radius is relative to `sqrt(w² + h²)/sqrt(2)`); positions also take `left`, `center`, `right`, `top`, and `bottom`. It cuts everything the element draws (box, shadows, filter, content, children), after the element's `filter`. Animate it with `clipPath` in `data-hf-keyframes`, for example an iris `[{"at":0,"clipPath":"circle(0% at 50% 50%)"},{"at":1,"clipPath":"circle(75% at 50% 50%)","easing":"ease-out-expo"}]`; every shape of one element must use the same function, number of points, and unit per value (the static `clip-path`, if any, sets them), keyframes without `clipPath` keep the previous shape, and the first and last shapes hold. `closest-side`/`farthest-side`, `evenodd`, `path()`, `url()`, box keywords, and CSS `@keyframes` clip paths are errors.
- `mask-image` (also `-webkit-mask-image`) takes one `linear-gradient()` or `radial-gradient()` laid over the border box; its alpha scales the element's (`mask-mode: alpha`), and everything outside the border box is hidden, for fades such as `mask-image: linear-gradient(to bottom, #000 60%, transparent)`. Image masks, `mask` shorthand, and mask sizing or repetition are unsupported. `clip-path` and `mask-image` render through an offscreen layer the size of the visible region, cannot be combined with rotate or `mix-blend-mode` on the same element (wrap it instead), and are not allowed on the root. See `examples/clip-mask.html`.
- Draw rounded backgrounds with a single nonnegative `border-radius` in px. The radius affects the background of the element. Supported gradients: `linear-gradient` with `to <side>`, `to <corner>`, or an angle (`deg`, `turn`, `rad`, `grad`), and `radial-gradient([circle|ellipse] [farthest-corner|farthest-side] [at <x> <y>], ...)` where the position uses keywords or %. Gradients take two or more stops, each `color [N%]` (px positions are unsupported); stops may be translucent and interpolate premultiplied. Gradients are dithered deterministically to avoid banding. `conic-gradient`, repeating gradients, and `closest-*` radial sizes return an explicit error. Fading a glow to `transparent` or `rgba(r,g,b,0)` works; use `farthest-side` with an ellipse so the edge of the box ends fully transparent.
- Fades use `data-hf-fade-in` and `data-hf-fade-out`, in seconds.
- Use `data-hf-keyframes` for native motion. The single-quoted HTML attribute contains a JSON array, for example `data-hf-keyframes='[{"at":0,"x":-80,"opacity":0},{"at":0.6,"x":0,"opacity":1,"easing":"ease-out"}]'`.
- Each keyframe requires `at` in seconds from the element's resolved start. Times must be strictly increasing within its duration. `x` and `y` are offsets in composition pixels that move the element and its children. `opacity` (0–1) multiplies existing opacity and fades. Omitted values inherit the previous keyframe's values and default to x=0, y=0, opacity=1.
- Keyframes can also animate `filter` amounts, which are absolute values rather than offsets: `blur` (px, 0 to 200), `brightness`, `contrast`, `saturate` (0 to 100), `grayscale`, `sepia`, `invert` (0 to 1), and `hueRotate` (degrees). For example, a focus-in is `[{"at":0,"blur":24,"opacity":0},{"at":0.9,"blur":0,"opacity":1,"easing":"ease-out-expo"}]`. A filter named in any keyframe gets a value at every keyframe: omitted values inherit the previous keyframe, and before the first one the element's static amount (or the neutral amount: blur 0, brightness/contrast/saturate 1, the rest 0). Overshooting easings are clamped to each range. See the `filter` entry for how animated functions combine with the static ones.
- Keyframes can also drive two pixel effects, inherited like filter amounts and 0 when absent: `glitch` (0 to 1: horizontal slices of the element jump sideways with a small channel split, in a pattern that changes 24 times a second and is a pure function of time) and `rgbSplit` (px, -500 to 500: red shifts left and blue right by that many composition px). For example `[{"at":0,"glitch":0.8,"rgbSplit":12},{"at":0.5,"glitch":0,"rgbSplit":0,"easing":"ease-out"}]`. They render through the effect layer (after the filter's color functions, before `drop-shadow`) and read only inside the element's box, so a full-size scene never shows holes at the frame edge.
- The destination keyframe sets the segment's easing. Available values are `linear` (default), `ease-in` and `ease-out` (quadratic), and `ease-in-out` (smoothstep). Premium curves are also accepted: `ease-{in,out,in-out}-{cubic,quart,expo,back}` (the `back` curves overshoot for a spring-like settle) and `cubic-bezier(x1, y1, x2, y2)`. The first and last values hold outside the keyed interval while the clip is active.
- `data-hf-camera` turns a non-root container into a camera: `data-hf-camera='[{"at":0,"zoom":1},{"at":2,"zoom":1.6,"x":200,"y":-80,"easing":"ease-out-expo"}]'`. `zoom` (0.05–50, 1 = neutral) scales the whole subtree around the container center; `x`/`y` are the focus point in px from that center, which the camera keeps centered while zooming (a pan). Omitted fields inherit the previous keyframe (zoom 1, focus 0,0 at first). Easing, hold, and `at` rules match `data-hf-keyframes`. Use a transparent full-size container inside the root (the root background does not zoom), and do not combine it with CSS animation or `data-hf-keyframes` on the same element. Add `overflow: hidden` on an outer wrapper if the zoomed-out scene must not bleed.
- `data-hf-draw` on an inline `<svg>` makes its strokes draw themselves along their length (line art, signatures, icons, routes): every `path`, `line`, `polyline`, `polygon`, `rect`, `circle`, and `ellipse` outside `<defs>`/`<clipPath>`/`<mask>`/`<symbol>`/`<marker>`/`<pattern>` is revealed with a dash pattern, in document order. Options: `data-hf-draw-at` (seconds from the clip start, default 0), `-duration` (seconds per shape, default 1.5), `-stagger` (seconds between the starts of consecutive shapes, default 0), and `-easing` (the `data-hf-keyframes` names, default `ease-in-out-cubic`). Fills are not animated (use `fill="none"` for pure line art, or fade the element), a shape's stroke is hidden until it starts, and once all strokes finish the SVG renders exactly as without `data-hf-draw`. The drawing must end inside the clip. Dash lengths are measured in each shape's own user space, so `transform` and `viewBox` scaling are respected; an existing `stroke-dasharray` on a shape is replaced while it draws. SVG files in `<img>` cannot draw (inline them), and up to 2000 shapes animate per `<svg>`. While drawing, the SVG is rasterized every frame.
- `data-hf-motion-path="<SVG path data>"` moves any non-root element along a path: its offset is the path's displacement from the path's first point (in composition px), so it starts where it rests; start the path at `M0 0`, or reuse the exact `d` of a drawn route and place the element on its first point. Options: `data-hf-motion-path-at` (default 0), `-duration` (default 2), `-easing` (default `ease-in-out-cubic`; overshoot clamps at the ends), and `-rotate` (`auto` turns the element with the path direction, `auto 90deg` adds an angle; default none). It adds to `data-hf-keyframes`, CSS animation, and camera offsets, must end inside the clip, and supports every path command (arcs included). `-rotate` counts as rotation (no `clip-path`, `mask-image`, or `data-hf-reveal` on the same element). See `examples/vector-motion.html`.
- `data-hf-split="words|chars"` makes plain text kinetic: the element becomes a flex row of per-word or per-letter pieces, each entering with a staggered motion. Text with `<br>` breaks becomes a column of such rows, one per line (each row spans the element and follows its `text-align`; an empty line keeps its height; a trailing `<br>` adds no line), and the stagger continues across lines. Options: `data-hf-stagger` (seconds between pieces, default 0.06), `data-hf-split-duration` (default 0.6), `data-hf-split-from` (`up` default, `down`, `left`, `right`, `scale`, `fade`, `mask`), `data-hf-split-distance` (px), `data-hf-split-easing` (same names as `data-hf-keyframes`, default `ease-out-expo`), and `data-hf-split-gap` (px between words, default 0.28 of the font size). Pieces start at the element's clip start. `mask` slides without fading; add `overflow: hidden` to the element for a line reveal. Alignment follows the element's own `text-align`. With `font-kerning: normal`, each letter of `chars` is kerned against the next letter of its word, so the pieces sit where the whole word would. Limits: lines break only at `<br>` (no automatic wrapping; a line wider than the element overflows), no child elements other than `<br>`, and at most 400 pieces. Set `font-size` on the element itself or pass `data-hf-split-gap` when the size is inherited.
- `data-hf-reveal="from-left|from-right|from-top|from-bottom"` uncovers the element (box, content, and children) from that edge, for growing bars, panels, and mask reveals. Options: `data-hf-reveal-at` (seconds from the clip start, default 0), `data-hf-reveal-duration` (default 0.8), `data-hf-reveal-easing` (default `ease-out-expo`). It is clipped to the revealed part of its box until complete, renders on an offscreen layer while partial, can be combined with other motion on the same element, and cannot be combined with rotate or placed on the root.
- `data-hf-counter="<end>"` turns an empty element into an animated number: `data-hf-counter="12400" data-hf-counter-from="0" data-hf-counter-duration="2" data-hf-counter-suffix="+"`. Options: `-from` (default 0), `-duration` (seconds, default 1.5, at most 10), `-delay` (seconds after the clip start, default 0), `-decimals` (0 to 6), `-prefix`, `-suffix`, `-separator` (thousands separator, default `,`; empty disables it), and `-easing` (names as in `data-hf-keyframes`, default `ease-out-cubic`). The element must have no text or children, takes its font from its own style, and aligns by its own `text-align`. The value is sampled 60 times per second, so each distinct string becomes one hidden-until-needed text piece.
- `data-hf-captions="<transcript file>"` turns an empty element into timed captions from a local `.json`, `.srt`, or `.vtt` file (never transcribed here): a `[{"text","start","end"}]` word array (`transcript.json`), OpenAI Whisper JSON (`words`, or `segments`), whisper.cpp JSON (`transcription`; token-level words when `tokens` are present), SRT, or WebVTT. Times are seconds from the element's clip start. Words are grouped into one-line cues at sentence ends, pauses, and length limits; SRT/VTT, and `segments` sources keep their own cues (their words get times proportional to length). Options: `data-hf-captions-mode` (`highlight` default, `reveal`, `plain`), `-highlight` (spoken-word color, default `#ffd60a`), `-pop` (spoken-word scale 1 to 2, default 1.08), `-offset` (seconds, may be negative), `-linger` (seconds a cue stays after its last word, default 0.3, never past the next cue), `-max-words` (default 8), `-max-chars` (default 40), `-pause` (default 0.8), `-preserve-cues` (one cue per entry, for single-word or CJK captions), and `-gap` (px between words). Give the element an explicit `left`, `top`, `width`, and `height`; rows sit at its top edge and follow its `text-align`, `color`, font, and `text-shadow`. A cue does not wrap, so size `font-size` and `-max-chars` to fit. At most 1200 words per element; split longer transcripts across several elements. `aether-motion captions <file> --to json|srt|vtt` converts and regroups transcripts. See `examples/captions.html`.
- `data-hf-transition="<kind>"` with `data-hf-transition-from="<outgoing id>"` joins two scenes (full-size clips) on the incoming clip; `data-hf-transition-easing` defaults to `ease-in-out-cubic`. The transition runs over the overlap `incoming.start .. outgoing.end`, so start the incoming clip early (for example `data-start="a-0.6"`) and give the outgoing clip a `data-duration` (overlap limit 10 s). The incoming clip must draw above the outgoing one (higher `data-track-index`, or the same track and later in the document). Kinds: `crossfade`; `push-left|right|up|down` (both scenes slide, the incoming one enters from the opposite side of the name's direction of travel); `cover-left|right|up|down` (the incoming scene slides over a static one); `wipe-left|right|up|down` (an edge travelling in that direction uncovers the incoming scene, antialiased, rendered through an offscreen layer); `zoom-in` (outgoing grows, incoming settles from 80%); `zoom-out` (outgoing shrinks, incoming settles from 120%); `dip-to-black` and `dip-to-white` (the outgoing scene goes to solid black or white over the first half of the overlap, then the incoming one emerges from it); `flash` (an overexposed white burst peaking at the cut); `blur` (the outgoing scene defocuses while the incoming one fades in and comes into focus, peak blur 3% of the short side); `whip-left|right|up|down` (a push whose scenes blur mid-flight); `glitch` (slices of both scenes jump sideways with a channel split, peaking at the cut, where the scenes swap); and `rgb-split` (red and blue separate up to 2% of the width, peaking at the cut). The light, focus, and glitch kinds draw both scenes through the effect layer only during the overlap; blurs fade the scene edges toward what is behind, as `filter: blur` does. A clip can enter and leave through two transitions if their windows do not overlap. Not combinable with CSS animation, `data-hf-keyframes`, or `data-hf-camera` on the same clip (wrap it in a container instead). Shader transitions are unsupported; wipes cannot be combined with rotate.
- CSS animation is compiled to native motion tracks. Define `@keyframes name { from {...} 40% {...} to {...} }` using only `transform` (`translate`, `translateX`, `translateY`, uniform `scale`, `rotate`), `opacity`, `filter`, and `animation-timing-function`. A keyframe's `filter` follows the static `filter` order rules and may list `blur()` and each color function once (not `opacity()` or `drop-shadow()`); each function interpolates on its own, and a function missing from a keyframe that lists `filter` takes its neutral amount there (so `filter: none` means all neutral), while keyframes without `filter` do not constrain it. Apply it with `animation: name 1s ease-out 0.2s 1 normal forwards` or the `animation-*` longhands (`name`, `duration`, `delay`, `timing-function`, `iteration-count` as a positive integer or `infinite`, `direction`, `fill-mode`). One animation per element. The animation starts at the clip start plus `animation-delay`. CSS semantics apply: without `forwards`/`backwards` the element returns to its resting style outside the animation. Do not combine with `data-hf-keyframes` on the same element.
- Easing in CSS animations follows CSS: `linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out` (cubic Béziers), `cubic-bezier(x1, y1, x2, y2)`, `steps(n, jump-start|jump-end)`, `step-start`, `step-end`. (`data-hf-keyframes` keeps its own quadratic easings.)
- `transform: translate(Xpx, Ypx) scale(s) rotate(a)` also works as a static style. Scale is uniform, grows around the element center, and scales descendants (positions, sizes, text, radius). `rotate(deg|rad|turn)` is clockwise around the center and can be animated like the rest. A rotated element is rendered on its own layer, so its descendants are clipped to its box plus its shadow reach. Skew, 3D, percent translations, and other transform origins are unsupported.
- Custom properties: declare `--name: value` on `:root` or any element (inherited) and use `var(--name, fallback)` in any supported value, including inside `@keyframes`.
- Composition variables make one composition a template rendered with different values. Declare them on `<html>` or on the element with `data-composition-id` (not both) as `data-composition-variables='[{"id":"title","type":"string","label":"Title","default":"Launch day"}, ...]'`. Each declaration needs `id` (a letter or `_`, then letters, digits, `_`, `-`; at most 64 characters; unique), `type`, `label`, and a `default` of that type, plus optional `description` and the fields of its type: `string` (`maxLength`, enforced; `placeholder`), `number` (`min` and `max`, enforced; `step`; `unit`), `color` (any supported color; `brandRole`), `boolean`, `enum` (`options`: strings or `{value, label}`, unique; the default must be one), `image` (a local path, or `{url, alt}`; `brandRole`), and `font` (a family name, or `{name}`). Unknown fields, a default of the wrong type, and more than 256 variables are errors. Bindings: `var(--id)` in any CSS value (each variable is set as `--id` on the composition root, over any declaration of `--id` on `:root` or the root itself; descendants may redefine it; a number takes its `unit` in CSS when it is `px`, `%`, `deg`, `turn`, `rad`, `grad`, `s`, or `ms`, otherwise it is the bare number; booleans are `true` or `false`); `data-var-text="id"` replaces the element's own text (child elements stay; the first direct text node takes the value, the others are emptied) and is an error on `img`, `video`, `audio`, `source`, `svg` and inside it, `style`, and the document elements; `data-var-src="id"` sets `src` on `img`, `video`, `audio`, or `source` from an `image`, `string`, or `enum` variable, and an empty value keeps the authored `src`; `data-var-if` removes the element and its subtree before parsing when its test is false: `id` or `!id` for booleans, `id=value` or `id!=value` for other types (numbers compare numerically, enum values must be options). It works on `<style>` elements too (for example a sheet per enum value), but not on the composition root, its ancestors, or `<head>`. A binding to an undeclared id, and any other `data-var-*` attribute, are errors. Values are a JSON object keyed by id; omitted ids keep their defaults, while unknown ids, wrong JSON types (`"60"` is not a number), out-of-range numbers, unknown enum values, and invalid colors are errors. Pass them with `--variables '{"title":"Q4"}'` or `--variables-file values.json` (`render`, `preview`, `check`, `bench`, `inspect`), as `"variables"` in `aether.json` (the flags override it id by id), or as the `variables` argument of `aether_check`, `aether_write`, `aether_snapshot`, and `aether_render`. `check` reports `variables`: each declared id with `type`, `value`, `default`, `overridden`, and `uses` (`css`, `text`, `src`, `if`, counted before any removal), plus `unused` ids and `removedElements`. Run `check` with each value set you plan to render, because values can change layout and safe-zone findings. See `examples/variables.html` and `examples/variables.json`.
- Colors: `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()`, `hsl()`, `hsla()`, `transparent`, and a set of common names.
- Flex layout: `display: flex` with `flex-direction: row|column`, `gap` (px), `padding` (1 to 4 px values or `padding-top/right/bottom/left`), `justify-content: flex-start|center|flex-end|space-between|space-around|space-evenly`, and `align-items: flex-start|center|flex-end|stretch` (stretch is the default). Items use `width`/`height`, or their content size (text, nested flex containers); `flex-grow: n` and `flex: n` share the free space. All children occupy their slot for the whole composition, whatever their clip timing, so layout never jumps when a clip starts. Children with `position: absolute` stay out of the flow and use `left`/`top` as before. `margin` (1 to 4 non-negative px values or `margin-top/right/bottom/left`) adds to an item's outer size and alignment happens in the margin box; on boxes outside the flow it offsets from `left`/`top`. `margin: auto` and negative margins are errors. There is no wrap, shrink, or `align-self`.
- Text wraps at spaces inside its box (`white-space: normal`, the default) and breaks into several lines when the content is wider than the box. The box width is the explicit `width`, otherwise the content width capped by the room the parent offers (the container's content width in flex) and by `max-width`. A flex column with the default `align-items: stretch` gives text the full container width. `white-space: nowrap` keeps one line. Lines are separated by `line-height`, a unitless multiple of `font-size` or a px value (default `1`), with the extra leading split above and below the glyphs. `text-align` applies to every line. A word wider than the box overflows instead of being split. Line breaks are decided at the unscaled font size, so they do not change with `--scale`, `--size`, or CSS `scale`. Only the element's own text is laid out, together with its inline runs (see the next entry); other child elements are boxes of their own, and newlines are not preserved; `line-height: normal`, `white-space: pre`, and `overflow-wrap` are unsupported. `<br>` forces a line break in the element's direct text (a trailing `<br>` adds no line). In a flex row text does not shrink below its content: it is capped at the container width, so siblings can still overflow, and `max-width` does not limit `flex-grow`.
- Inline rich text: when an element has text of its own, its `<span>`, `<strong>`, `<b>`, `<em>`, `<i>`, and `<code>` children (nested, with `<br>`) become styled runs of that text, wrapped and aligned with it: `<h1>Make <span class="accent">motion</span> natively</h1>`. Whitespace collapses as written in the source, so `Make<span>s</span>` stays one word. A run may set `color`, `font-family`, `font-weight` (`<strong>`/`<b>` default to 700, `<code>` to `monospace`), `font-style` (`<em>`/`<i>` default to italic), `letter-spacing`, `-webkit-text-fill-color`, `-webkit-text-stroke`, and a `background` with `background-clip: text` (a gradient across the run's extent on each line). Anything that makes a run a box (size, position, padding, margin, border, a background without `background-clip: text`, opacity, transforms, filters, `font-size`, `line-height`, `text-shadow`, `data-*` attributes, the `clip` class, animation) is an error, as is `font-kerning` on a run (set it on the text element; pairs kern within one run); other tags (`a`, `u`, ...) are unsupported. An element whose only content is a `<span>`, or that has `data-var-text`, keeps its spans as child elements, as before.
- `-webkit-text-fill-color` (inherited) paints the glyph fill in place of `color`; `-webkit-text-stroke: <width> [<color>]` (also `-webkit-text-stroke-width` and `-color`, inherited; `thin`, `medium`, `thick` are 1, 3, 5 px; color defaults to `color`) strokes the glyph outlines centered on their edges, over the fill, from the real font outlines. `color: transparent; -webkit-text-stroke: 3px #4a7dff` gives outline type. `background-clip: text` (also `-webkit-background-clip`; only `text` and `border-box`) paints the element's background inside its glyphs instead of its box, laid over the padding box, under the text's own fill: pair it with `color: transparent` for gradient text. It needs text of its own and a background. `text-shadow` follows the glyph shapes, not the stroke. See `examples/rich-text.html`.
- `text-shadow: offset-x offset-y [blur] color`: one soft shadow of the glyphs, inherited like `color`; `none` resets it. The color defaults to black, there is no spread, and `inset` and lists are unsupported. The blur radius follows CSS (standard deviation of half the radius). The shadow is painted under the text, follows opacity, fades, scale, and rotation, and shifts as one block, so its offset is rounded to whole pixels. On a rotated element, only that element's own text shadow is guaranteed to stay inside its layer.
- `box-shadow: [inset] offset-x offset-y [blur [spread]] color [, ...]`: up to 8 soft shadows (the first paints on top) that follow `border-radius`, scale, and opacity, for layered depth and glows. `inset` shadows are cast inside the padding box (above the background, below the border and content) and can be mixed with outer ones.
- `backdrop-filter: blur(Npx)` (also `-webkit-backdrop-filter`; `none` resets; at most 200 px) blurs what is already painted behind the element, inside its rounded box, before its own background is drawn. Pair it with a translucent background such as `rgba(255, 255, 255, 0.12)` and a `border` for glass cards. Only blur is supported, and elements drawn earlier (lower track or earlier in the document) are what gets blurred. Inside `overflow: hidden` or rotated elements it sees that element's layer, not the whole scene.
- `filter` (also `-webkit-filter`; `none` resets) takes, in this order, an optional `blur(Npx)` (at most 200 px), any number of color functions (`brightness`, `contrast`, `saturate`, `grayscale`, `sepia`, `invert`, `opacity` with a number or %, and `hue-rotate` with `deg`, `turn`, `rad`, or `grad`; at most 16), and an optional `drop-shadow(x y [blur] color)` (no spread). Other orders, `url()`, and other functions are errors. On an element, it applies to the whole element (box, outer shadows, content, and children) through an offscreen layer padded by the blur and shadow reach, so content more than that reach outside the element's box (plus its shadow reach) is cut, and inside it `backdrop-filter` sees that layer. Color functions follow the Filter Effects matrices in sRGB, clamped after each function. `drop-shadow` follows the painted shape (transparent PNG and SVG pixels cast none) and draws under the element. On the root, only color functions other than `opacity()` are allowed: they grade every finished frame before vignette and grain. Filter amounts are animatable with `data-hf-keyframes` and CSS `@keyframes` on non-root elements (to grade the whole frame over time, animate a full-size container); `drop-shadow` and `opacity()` are not. Animated color functions take the place of the same function in the static `filter`; animated functions it does not list apply after it, in the order brightness, contrast, saturate, grayscale, sepia, hue-rotate, invert; an animated function may appear at most once in the static `filter`. An animated blur uses a continuous kernel (an extended box filter with the exact gaussian variance), so its strength changes smoothly frame to frame; a static blur keeps the whole-radius kernel. At instants where every function is neutral, the element is drawn directly, exactly as without a filter.
- `mix-blend-mode: normal|multiply|screen|overlay|darken|lighten|color-dodge|color-burn|hard-light|soft-light|difference|exclusion|plus-lighter` blends the element (with its subtree, as one layer) with everything drawn behind it, in sRGB. Not allowed on the root or inside an element drawn through an offscreen layer (`overflow: hidden`, rotation, `data-hf-reveal`, a wipe, a `filter`, a `glitch`/`rgbSplit` effect, `clip-path`, `mask-image`, or another blend mode): move it out of that element. `hue`, `saturation`, `color`, and `luminosity` are errors.
- `data-motion-blur="on"` on the composition root adds shutter motion blur: each frame averages several instants over a window of `data-motion-blur-shutter` degrees of one frame (above 0 to 720, default 180, centered on the frame time). `data-motion-blur-samples` (2 to 64) fixes the count; without it each frame takes about one sample per 2 output px of the fastest element's travel (translation, plus rotation and scale measured a quarter of the frame's short side from the center), 8 to 64. Frames in which nothing moves inside the window (no visible element changes position, scale, rotation, or reveal; fades, filters, and video frames do not count as movement) are drawn once at the frame time, sharp, and reuse identical frames as before. Snapshots (`render_at`, `aether_snapshot`) assume 30 fps for the window. A blurred frame costs about one full draw per sample, so prefer `data-motion-blur-samples="8"` for drafts. Output stays deterministic.
- `data-hf-vignette` and `data-hf-grain` (0 to 1) on the composition root darken the corners and add monochrome film grain to every frame (after the root's color grade and motion blur). Grain is reseeded from the frame time, so it is deterministic but disables the identical-frame shortcut and costs a full-frame pass.
- `border: Npx solid color` (also `border-width`, `border-color`, `border-style: solid|none`): a uniform solid border that follows `border-radius`. Sizes are border-box, so the border sits inside `width`/`height` and insets content and flex children. The color defaults to white. Per-side, dashed, and dotted borders are unsupported.
- Network access, `Date.now()`, and randomness are unsupported. Use relative paths.
- `<audio src="file.wav">` adds sound. It is not a visual element: it takes no part in layout or painting and may sit anywhere in the root. Sources are local WAV, FLAC, Ogg Vorbis, MP3, or AAC-in-MP4/M4A files, mono or stereo at any sample rate; other formats, remote URLs, and more than two channels are errors. Attributes: `data-start` (seconds or `id+offset`, as for clips; defaults to the start of the enclosing clip), `data-duration` (defaults to the rest of the source, capped at the composition end; the clip must fit the composition), `data-volume` (linear gain 0 to 8, default 1), `data-hf-fade-in` and `data-hf-fade-out` (seconds, linear in amplitude), `data-hf-trim-start` (seconds skipped at the start of the source), and `data-hf-loop` (`true` repeats the trimmed source until `data-duration`, which is then required; the cut is hard, so loop only seamless sources). Audio is not cut by its enclosing clip. All clips are mixed by summation onto one 48 kHz stereo timeline; mono plays on both channels. Every time becomes a whole sample with `round(seconds * 48000)`, and a clip's length is the difference of its rounded end and start, so clips that meet at one time neither overlap nor leave a gap. Sources at other rates are converted with a deterministic Kaiser-windowed sinc resampler. `aether_check` and `check` decode every file and report `audio` (`clips`, `peak`, and `clippedSamples`); keep `peak` at or below 1.0, because louder samples are clamped. MP4 output carries one AAC-LC track (192 kbit/s by default; `--audio-bitrate` 64 to 320 kbit/s, or `audioBitrate` in `aether_render`), with an edit list that hides the encoder delay so audio starts on the first video frame. The native encoder only: `--encoder ffmpeg` rejects `<audio>`. The mix is limited to about 22 minutes and each decoded source to 128 million samples.
- `<video src="clip.mp4">` plays a local H.264 `.mp4` (or `.mov`) as a clip, one source frame per output frame, drawn like an image: it needs an explicit `width` and `height`, and `object-fit` (`fill` default, `contain`, `cover`) applies. Attributes: `data-start`, `data-duration` (defaults to the source length minus `data-media-start`), `data-media-start` (seconds into the source, default 0), `loop` or `data-hf-loop` (repeat the source; needs `data-duration`), `muted`, `data-volume` (0 to 8), and `data-hf-fade-in`/`data-hf-fade-out` (picture and sound). Without `loop`, the last frame holds when the source ends. Fades, keyframes, transforms, `overflow: hidden`, and the other element effects work as on images. If the source has an AAC audio track and the element is not `muted`, that sound is mixed like an `<audio>` clip: it starts with the clip, is trimmed by `data-media-start`, lasts as long as the clip, and loops with it over the whole source, exactly like the picture (the loop cut is hard). `check` reports `videos` with `audioMixed`. Rotation metadata (90, 180, 270) is applied; mirroring is an error. Supported sources are 8-bit 4:2:0 H.264 (Baseline, Main, or High) without B-frames in a non-fragmented MP4 with closed GOPs (a source whose frames are reordered for display is rejected at parse time with `ffmpeg -i in.mp4 -c:v libx264 -bf 0 -x264-params open-gop=0 -c:a copy out.mp4`, because the built-in decoder cannot decode B-frames), at most 16 megapixels and 200,000 frames; anything else is an explicit error with a re-encode command. Each render thread decodes independently from the nearest keyframe, so long GOPs make seeking slower. Color follows the SPS tags: BT.601 or BT.709 matrix and limited or full range (untagged HD pictures are read as BT.709, others as BT.601); `check` reports `colour`. `check` decodes the first and last frame and reports frames, keyframes, fps, size, duration, and `rotation`. A single `<source src>` child (the first MP4 one) works in place of `src`; `poster`, `autoplay`, `controls`, and `preload` are accepted and ignored. Not supported: remote sources, the `playbackRate` property (use `data-hf-speed`), HEVC/VP9/AV1, and WebM.
- Variable speed on `<video>` and `<audio>`: `data-hf-speed="0.5"` plays at a constant rate (0.05 to 16; 1 is normal) and `data-hf-speed-ramp` ramps it: `data-hf-speed-ramp='[{"at":0,"speed":1},{"at":1.2,"speed":0.25,"easing":"ease-in-out-cubic"},{"at":3,"speed":0.25},{"at":3.6,"speed":2}]'`. `at` is seconds from the clip start (strictly increasing, at most 3600, at most 256 keyframes), `speed` is the rate reached there (0 to 16; omitted values inherit the previous keyframe, 1 at first), and `easing` (the `data-hf-keyframes` names) shapes the segment that ends at that keyframe; the first and last rates hold outside the keyed interval, and overshooting easings are clamped to 0..16. Use one attribute or the other, not both; a ramp needs at least one keyframe with a nonzero speed (an all-zero ramp is an error even with `data-duration`). Source time is the integral of the rate, so the picture never jumps when the rate changes. `data-media-start` and `data-hf-trim-start` stay source-time offsets (a value of 2 skips two source seconds at any speed), while `data-duration`, `data-start`, and fades stay in clip time; `loop`/`data-hf-loop` wraps source time as before. Without `data-duration`, the clip lasts until the source (after the trim) is used up at that speed (`0.5` doubles the length); a ramp that ends at speed 0 freezes on its last frame and needs `data-duration`. A video's own sound follows its picture's rate. Sound is varispeed, like tape: pitch follows the rate (`0.5` is an octave down); it is read through an antialiased windowed-sinc interpolator, and below 0.05x it fades linearly to silence, so a ramp to 0 ends as a tape stop. Slow motion repeats source frames (there is no frame interpolation): for smooth slow motion use a high-frame-rate source (a 120 fps clip at `0.25` gives a new frame every 30 fps output frame); fast speeds decode every intermediate source frame. `check` reports `speed` (`{"speed": n}` or `{"ramp": [...]}`) and `mediaEnd` (source seconds at the clip end, before looping) for each video clip, and `speed` and `mediaSeconds` (source seconds played) for each audio clip. See `examples/speed.html`.
- Audio effects on `<audio>` and on the sound of an unmuted `<video>` (a muted or silent video with them is an error). The chain is source (and speed) -> equalizer -> `data-volume` x fades x automation x ducking -> mix; a clip without effects mixes exactly as before. `data-hf-volume-ramp='[{"at":0,"volume":1},{"at":2,"db":-12,"easing":"ease-in-out"},{"at":6,"db":-12},{"at":8,"volume":0}]'` automates the gain: `at` is seconds from the clip start (strictly increasing, 0 to 3600, at most 256 keyframes), each keyframe sets `volume` (linear 0 to 8) or `db` (at most +18), not both (omitted values inherit, 1 at first), `easing` (the `data-hf-keyframes` names) shapes the segment ending there, and the first and last values hold outside the keyed interval; it multiplies `data-volume` and the fades, and is evaluated every 32 samples (1.5 kHz control rate) with linear interpolation in between, which is exact on held and linear segments and smooths `steps()` edges over 0.67 ms. `data-hf-eq` is a preset (`voice`: 80 Hz high-pass, -2 dB at 250 Hz, +3 dB at 3.5 kHz, +2 dB shelf at 10 kHz; `music-bed`: 40 Hz high-pass, -5 dB at 2.5 kHz to leave room for speech, -1 dB shelf at 12 kHz; `telephone`: 300 Hz to 3.4 kHz band with +3 dB at 1.5 kHz; `warm`; `bright`) or a JSON list of up to 16 bands `[{"type":"highpass","freq":80},{"type":"peak","freq":3000,"gain":3,"q":1},{"type":"highshelf","freq":10000,"gain":2}]`: types `highpass`, `lowpass`, `bandpass` (0 dB peak), `notch`, `peak`, `lowshelf`, `highshelf`; `freq` 10 to 20000 Hz; `gain` -24 to 24 dB, required on `peak` and the shelves and rejected on the others; `q` 0.1 to 30 (default 0.7071 for the pass and shelf filters, 1 otherwise). Bands are RBJ cookbook biquads at 48 kHz, filtered in f64 from a zero state at the clip start. `data-hf-duck="voice[,id2]"` lowers this clip (typically music) while the listed clips (any `<audio>` or unmuted `<video>` with an `id`) sound: a trigger is active when its post-effects louder channel exceeds `data-hf-duck-threshold` (dBFS, -90 to 0, default -40); the reduction of `data-hf-duck-amount` dB (0 to 60, default 12) is reached at the voice onset because it starts `data-hf-duck-attack` seconds early (look-ahead, default 0.15), stays for `data-hf-duck-hold` after the last active sample (default 0.15, bridges syllables), and returns over `data-hf-duck-release` (default 0.5); times are 0 to 5 s, the ramps are smoothstep-shaped in dB, and the `-amount`, `-threshold` values may end in `dB`. Ducked clips are mixed after their triggers (self references and cycles are errors; options without `data-hf-duck` are errors). `check` and `aether_check` report `audio.clips[].effects`: `volumeRamp` (`at`, `volume`, `db`), `eq` (`preset`, `bands`, and `responseDb` at 50 Hz to 16 kHz), and `duck` (`by`, the settings, `regions` as `[start, end]` seconds where at least half the reduction applies, `duckedSeconds`, and `deepestDb`). Confirm the regions line up with the speech and that `peak` stays at or below 1.0. See `examples/audio-effects.html`.
- Unsupported features return an explicit error; never silently produce a wrong video. This includes `<script>`, GSAP, `<iframe>`, canvas, and general CSS. SVG is supported only as static artwork under the limits described above; SVG text, animation, scripts, and external resources are unsupported.

## CPU budget

- Output is identical for every thread count, render split, and CPU. Cached layers (gradient and shadow tiles) and their uncached first draws compute the same fixed-point texels, so whether a tile exists never changes a pixel. Hot per-row loops live in `render/paint/kernels.rs` as branch-free scalar code that is also compiled for AVX2 and chosen at run time; they never enable FMA or reassociate arithmetic, so both builds produce the same bits. `AETHER_SIMD=off` forces the baseline build, to compare speed or confirm identical output. A new kernel needs a test against the scalar loop it replaces.

- A render's total CPU work is fixed; extra threads only finish it sooner. The defaults favor a responsive machine: `--threads` defaults to a quarter of the cores (1 to 4) and the process lowers its priority (`--priority low`, `nice 10`; `--priority normal` opts out).
- Layers that repeat at the same size across frames (square-cornered gradients and soft box shadows) are rasterized once into `paint/tile_cache.rs` tiles (64 MiB per surface) and only blended afterwards. Tiles are built on the second sighting, so snapshots never pay for them. Effect layers other than a static blur (color filters, `drop-shadow`, blend modes, animated filters) share the frame's caches; the caches are frozen while the layer's black and white passes run (tiles built meanwhile become usable afterwards), so both passes take the same cached or direct decisions. When adding a cached primitive, key it by everything its pixels depend on and add a test against the direct path.
- Wide `backdrop-filter` blurs (sigma of 16 px or more) run on a 2x or 4x reduced copy scaled back up bilinearly; narrower blurs and small regions stay full size. Any change to this path must keep the error against the full-size blur at 2 levels or less on real frames (`BENCHMARK.md` lists the method and numbers), and every other speedup must keep output byte-identical.
- Build once, measure many times. Release builds with LTO use several cores for tens of seconds, so batch all code edits first, then run a single `nice -n 15 cargo build --release -j 1`, and measure with the binary already in `target/release`. Do not rebuild between measurements or for each small idea, and do not create extra build directories (for example symbol builds) unless profiling truly needs one.
- Measure with `bench --frame START --count N` on 15 to 20 frames at one thread instead of rendering whole compositions. Never run `cargo test` for the whole suite repeatedly: it builds separate test binaries and recompiles the crate. Run one targeted test, once, when a change touches that code.
- Keep tests light: run targeted tests (`cargo test --release <name>`) at low priority, and compare images with small tools in a language other than Python.
- Profile before changing hot paths, and record the before and after in `BENCHMARK.md`.

## Benchmark privacy

- Preserve measured benchmark and test results, including timings, memory use, output sizes, and comparisons. Do not delete or alter them merely to sanitize a document.
- Remove only private machine-identifying metadata: exact hardware models, local operating-system versions or builds, host architecture when it identifies the user's device, hostnames, usernames, serial numbers, and user-specific local paths. Describe the machine generically or omit that metadata.
- Keep the benchmark settings needed to interpret results. Never add identifying device details to tracked documentation.

## Blocks and themes

Prefer ready-made pieces over hand-written scenes. `aether-motion block list` (or `aether_block` without a name) shows every block with its parameters and defaults; `aether-motion block <name> --set key=value` (or `aether_block` with `name` and `params`) prints HTML to paste into the composition. Blocks target 1920x1080, take a unique `id` (it prefixes their classes and keyframes), inherit timing from the clip that contains them, and read colors from custom properties (`--bg`, `--text`, `--muted`, `--accent`, `--accent-2`, `--on-accent`, `--panel`, `--line`, `--glow-a`, `--glow-b` and their `-fade` variants). Add a theme block (`theme-midnight`, `theme-sunrise`, `theme-paper`) to recolor everything, and set the root background to `var(--bg)`. See `examples/premium-promo.html`.

## MCP

`aether-motion mcp` speaks MCP over stdio. It implements protocol version `2026-07-28` and accepts legacy clients that begin with `initialize`. Tools: `aether_guide`, `aether_write`, `aether_block`, `aether_check` (also returns `layout.findings`; optional `safeZone`, `captionZone`, `samples`, and `at` mirror the `check` flags), `aether_snapshot` (returns an image), and `aether_render`.

For motion, read the `animations` entries from `aether_check` and inspect the start, midpoint, and end of a transition with `aether_snapshot`. Its `t` argument is an absolute composition time in the range `0 <= t < duration`. See `examples/motion.html`.

`aether_render` sends `notifications/progress` (`progress` and `total` in frames, a `message` with fps and ETA) while it encodes when the `tools/call` request carries `_meta.progressToken`, at most four per second and always for the last frame.

For a composition that declares variables, pass `variables` (an object keyed by id) to `aether_check`, `aether_write`, `aether_snapshot`, and `aether_render`; omitted ids keep their defaults.

Pass `size: "1080p"` or `size: "4k"` (16:9 gives 1920x1080 / 3840x2160; 9:16 gives 1080x1920 / 2160x3840) to `aether_snapshot` or `aether_render`. Specify either `size` or `scale`. For native MP4, use `fps` from 1 to 60, `threads` from 1 to 64, and `quality` (`draft`, `standard` (the default), `high`, or `max`).
