# AETHER Motion architecture

Source layout and resource limits of the native renderer. Contributor rules (CPU budget, benchmarking, tests) live in [AGENTS.md](../AGENTS.md); measurements live in [BENCHMARK.md](../BENCHMARK.md).

## Source layout

- `src/model.rs`: parsed composition, styles, and time-sampled motion tracks.
- `src/parse/`: HTML/CSS parser; unsupported features fail with explicit errors. `mod.rs` is the `parse_file` facade; `css/` (stylesheet, selectors, cascade, variables), `values/` (lengths, colors, backgrounds, transforms, shadows), `style/` (layout, text, and visual property groups), `animation/` (CSS animation, `data-hf-keyframes`, and `data-hf-camera` into motion tracks), `split.rs` (`data-hf-split` kinetic text), `captions.rs` (`data-hf-captions` rows of per-word highlight pieces built from a transcript), `transition.rs` (`data-hf-transition` scene transitions), `tree.rs` (DOM walk), `timeline.rs` (`data-start`), `audio.rs` (`<audio>` attributes into `AudioClip`s, kept outside the element tree), `html.rs` (node helpers).
- `src/render/`: software renderer. `mod.rs` holds the public `Renderer` and frame loop; `draw.rs` walks the scene; `layout/` sizes and places flex items; `paint/` holds the `Surface` pixel buffer and its primitives (fills, gradients and soft shadows backed by a memory-bounded tile cache in `tile_cache.rs`, borders, outer and inset box shadows, backdrop and element blur, images with cached row spans, rotation, and the vignette/grain `finish` pass); `text/` handles fonts, inherited properties, line wrapping (`wrap.rs`), block layout (`block.rs`), glyph painting with fixed-size coverage masks and subpixel resampling (`mask.rs`) for continuous translation/zoom, and `text-shadow` (`shadow.rs`); `allocation.rs` checks frame/layer byte sizes and coordinate conversions; `geometry.rs` and `frame_state.rs` hold small shared types.
- `src/captions/`: transcript domain, independent of HTML and rendering. `transcript.rs` imports `transcript.json`, OpenAI Whisper and whisper.cpp JSON, SRT, and VTT into timed words; `cues.rs` groups words into cues; `export.rs` writes SRT, VTT, and the word array. It never transcribes audio.
- `src/video/`: `<video>` sources. `colour.rs` reads SPS colour tags and converts non-default pictures; `index.rs` reads the MP4 sample tables (no decoding) into display-order frame times and closed GOPs at parse time; `player.rs` decodes on demand with OpenH264, seeking to the GOP keyframe and decoding forward (closed GOPs make decoder output order equal display order); `annexb.rs` converts length-prefixed NAL units. `parse/video.rs` builds `Content::Video` (and, unless `muted`, an `AudioClip` for the source's AAC track, decoded through the same path as `<audio>`), `render/paint/video.rs` fits and blits the frame, and each renderer fork owns one player per element.
- `src/blocks/` and `blocks/`: ready-made blocks and themes. `blocks/*.html` are `{{name|default}}` templates embedded by `catalog.rs`; `template.rs` fills them; `mod.rs` serves the `block` CLI command and the `aether_block` MCP tool.
- `src/audio/`: sound. `decode.rs` (symphonia: WAV, FLAC, Ogg Vorbis, MP3 into planar `f32`), `resample.rs` (polyphase Kaiser sinc to 48 kHz), `mix.rs` (sample-accurate placement, trim, loop, fades, and volume onto one stereo timeline, plus clipping statistics), `aac.rs` (AAC-LC through the pure-Rust `oxideav-aac`, ADTS headers stripped; the crate is vendored in `vendor/oxideav-aac` with a table-driven forward MDCT, see its `AETHER-PATCH.md`), `mux.rs` (MP4 audio track, interleaving, and the `moov` patch that adds the edit list); `mod.rs` is the `build_track` facade.
- `src/cli/`: human-facing subcommands (`init`, `preview`, `render`, `check`, `add`, `captions`, `agent`, `doctor`). `mod.rs` is the dispatcher (legacy flag forms stay in `main.rs`), `args.rs` parses flags, `project.rs` reads `aether.json` and resolves the entry file, one file per command.
- `src/setup/` and `templates/`: agent wiring used by `init` and `agent setup`. `skills.rs` embeds `skills/` into the binary and writes it to `.claude/skills` and `.agents/skills` (a test fails when a skill file is missing from the table); `mcp_config.rs` detects agents and merges the `aether-motion` server into project-scoped MCP JSON. `templates/` holds the sample projects and `AGENTS.md`.
- `npm/`: npm distribution. `cli/` is the `@aether-motion/cli` launcher (Node shim that runs the platform binary), `scripts/build-packages.mjs` assembles it and the per-platform packages from release artifacts. See [releasing.md](releasing.md).
- `src/encode.rs`: native H.264/MP4 encoding, with the optional AAC track interleaved by a small `Muxer`. `src/agent.rs`: structured composition checks and the agent facade; `src/agent/zones.rs`: safe-zone and caption-zone text checks, fed by `render/probe.rs` (a read-only layout probe that records text ink boxes during the normal draw pass); `src/agent/mcp.rs`: the MCP stdio protocol server and tool handlers.

## Memory and resource limits

The renderer keeps one RGBA frame, up to 64 MiB of scaled images, and up to 32 MiB of text masks. When the visible state matches the previous frame, it reuses the RGBA frame and the native encoder's YUV conversion.

Each gradient or outer-shadow tile cache retains at most 4,096 keys, including first sightings and rejected tiles. Exceeding that metadata limit returns an explicit render error; existing slots are not evicted or changed, preserving the cached/direct drawing decisions. Reduce animated size variation or split the composition when this limit is reached. Fitted-image and text-run caches also retain at most 4,096 entries; image eviction and uncached text preparation retain the same pixel calculations. Text-layout blocks already have a 4,096-key cap.

Frames and offscreen RGBA layers keep their 128 MiB per-buffer limit, with checked multiplication and widened coordinate subtraction before allocation. Rotation and element blur reject unrepresentable pixel coordinates. Shadow-edge profiles are limited to 16 MiB before allocation. These are per-resource bounds, not a guarantee of total process memory or successful allocation under memory pressure.

## Video

A `<video>` element is indexed when the composition is parsed: the container's `stts`, `ctts`, and `stss` tables give each frame's presentation time and the keyframe groups, so the clip length and the frame shown at any time are pure functions of the composition. The frame shown `local` seconds into the clip is the last source frame whose time is not after `media_start + local` (looped sources wrap by the source length; otherwise the last frame holds). The source frame index is part of the element's `FrameState`, so the identical-frame shortcut still applies when the source runs slower than the output.

Decoding happens at render time, per renderer: a request for frame `k` starts a fresh decoder at the keyframe of its GOP (or continues when `k` is ahead in the same GOP) and decodes forward, so sequential rendering decodes each frame once and a backward jump costs up to one GOP. Rotation metadata is applied when the picture is converted. Sources with open GOPs, fragmented MP4s, mirroring, and non-H.264 codecs are rejected at parse time. The decoded picture is converted to RGBA at source size (`video/colour.rs` reads the SPS matrix and range; limited-range BT.601 uses the decoder's own conversion, everything else a fixed-point integer one), fitted to the element box with `object-fit`, and blitted opaque (no tile cache). Memory per player is the current picture plus the few pictures the decoder's reorder delay releases at once; each render thread has its own players, so 4K sources cost roughly 33 MiB per picture per thread. Decode cost per frame has not been measured yet; see `BENCHMARK.md` once added.

## Audio

Audio is built once, on the calling thread, before the video is encoded, so the result does not depend on `--threads` (it costs about a third of real time per audio track; see `BENCHMARK.md`). The mix has two `f32` planes (8 bytes per sample frame, capped at 512 MiB, about 22 minutes); each decoded source is capped at 128 million samples (512 MiB) and is held once at 48 kHz per distinct file.

Timing is exact by construction. Times become samples with `round(seconds * 48000)`, the track spans `round(frames * 48000 / fps)` samples, and AAC frames of 1024 samples are written after the video frame during which they start. The encoder primes its first frame with 1024 zero samples; an `elst` edit list (media time 1024, duration equal to the video) hides them, and `mvhd`/`tkhd` durations equal the video's. The `mp4` crate writes no edit list, so `audio/mux.rs` rewrites the final `moov` box after the file is closed. Tests decode the MP4 audio and check a burst lands on the expected sample (see `tests/audio.rs`), and macOS `afconvert` decodes the same file to the same sample.

## Encoding

Both encoders produce H.264/yuv420p at a constant frame rate. The native encoder (OpenH264) is built in; `--encoder ffmpeg` uses FFmpeg from `PATH` with `veryfast` and CRF 25 (video only: compositions with `<audio>` need the native encoder). Audio is AAC-LC, 48 kHz stereo, at 192 kbit/s by default. For native exports at 1080p or higher, `--threads 2` or more overlaps drawing and color conversion with encoding through a one-frame queue.
